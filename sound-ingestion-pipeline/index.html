    Sound Ingestion And Training Pipeline¶

    This page documents the current sound ingestion, sound dataset preparation, and sound-classifier training flow.

    It started as a xeno-canto ingestion pipeline, and now also includes:

    • Dropbox Definitive MP3 imports
    • xeno-canto training-clip top-up across already-covered species
    • Wikimedia Commons audio import
    • species-labeled sound training dataset preparation
    • first-pass sound-classifier training

    Key scripts:

    • bird-agent/download_xeno_canto_sounds.py
    • bird-agent/sync_species_sounds.py
    • bird-agent/sound_rag.py
    • bird-agent/check_bird_sound_ingestion_progress.py
    • bird-agent/query_species_sounds.py
    • bird-agent/backfill_xeno_canto_sound_metadata.py
    • bird-agent/run_next_sound_ingestion.py
    • bird-agent/run_sound_ingestion_loop.py
    • bird-agent/check_sound_ingestion_status.py
    • bird-agent/media.py
    • bird-agent/import_commons_bird_sounds.py
    • bird-agent/ai/prepare_sound_training_data.py
    • bird-agent/ai/import_definitive_mp3_sounds.py
    • bird-agent/ai/train_bird_sound_classifier.py
    • bird-agent/ai/decode_audio.swift
    • sound-training-curation-flow.md

    It is intentionally split into:

    • ingestion into canonical app sound fields
    • metadata-first retrieval
    • labeled dataset preparation
    • model training
    • supporting loop and audit scripts

    Source Strategy¶

    Primary source:

    • xeno-canto

    Why it fits:

    • free public bird recording archive
    • searchable API and downloadable file links
    • rich metadata per recording
    • broad global species coverage

    Important constraint:

    • licenses are per recording, so ingestion must always keep the original license and attribution metadata with the stored file

    Relevant official references:

    • xeno-canto API
    • xeno-canto home
    • example recording pages with license and technical metadata:
    • XC51247
    • XC905260

    Current Database Shape¶

    The current app-facing fields stay in bird_species:

    • song_audio_url
    • call_audio_url

    Those remain the fast selected pointers used by the mobile app.

    The current source-of-truth table is:

    bird_species_sound_sources¶

    Column Type Purpose
    id INTEGER Primary key
    bird_species_id INTEGER Foreign key to bird_species
    source_name TEXT Usually xeno-canto
    source_recording_id TEXT xeno-canto recording id such as XC905260
    source_page_url TEXT Canonical xeno-canto recording page
    download_url TEXT Original downloadable audio URL from the source
    storage_path TEXT Internal stored file path, local or Firebase-style
    audio_role TEXT song or call
    license_name TEXT Full license string
    recordist TEXT Original recordist attribution
    quality_grade TEXT Quality rating such as A or B
    recording_type TEXT song, alarm call, flight call, etc
    country TEXT Recording country
    location TEXT Free-text location
    recorded_at TEXT Date/time text if available
    duration_seconds REAL Audio length
    remarks TEXT Recordist remarks
    background_species TEXT Other species listed in the recording
    channels INTEGER Mono/stereo style channel count if known
    sample_rate_hz INTEGER Audio sampling rate if known
    is_selected INTEGER 1 when this row is the current chosen exemplar
    created_at TEXT Insert timestamp
    updated_at TEXT Update timestamp

    Current indexes:

    • unique source_name, source_recording_id, audio_role
    • index on bird_species_id, audio_role
    • index on bird_species_id, is_selected

    Current Script Layout¶

    1. Discovery and download¶

    Base script:

    • bird-agent/download_xeno_canto_sounds.py

    Current responsibilities:

    • query xeno-canto by scientific name first
    • fall back to common-name aliases when needed
    • capture raw metadata for selected recordings
    • filter candidates by:
    • allowed license
    • preferred quality
    • preferred recording type
    • reasonable duration
    • download the top selected song and call candidates
    • enrich selected rows from the recording detail pages when needed
    • write rows into bird_species_sound_sources

    Current newer capability:

    • --additional-training-clips N
    • download extra song recordings beyond the canonical selected pair
    • store them as training_song
    • keep them non-selected so app playback stays stable

    Current newer top-up mode:

    • --top-up-all-species
    • scan the full species table, not just species still missing canonical song/call
    • top up only the training-only clip depth
    • leave selected song / call rows unchanged

    This is currently the best path for deepening the training dataset from xeno-canto alone.

    1a. Training clip scoring¶

    Extra xeno-canto training clips are no longer chosen only by broad role and raw quality rank.

    The downloader now applies a dedicated scoring function:

    • score_training_sound_clip(...)

    Current scoring preferences:

    • prefer song recordings over call-like roles
    • prefer quality grades:
    • A
    • then B
    • then lower grades
    • prefer moderate training-friendly durations:
    • roughly 5 to 20 seconds strongest
    • penalize clips with:
    • background_species
    • noisy recordist remarks
    • distant / traffic / wind / overlap style notes
    • penalize weak role hints such as:
    • alarm
    • flight call
    • subsong

    This gives the pipeline a more learnable training subset than simply "all available song mp3 files."

    Conceptually, the score behaves like:

    score =
  quality score
  + song-role preference
  + useful-duration bonus
  - background-species penalty
  - noisy-remarks penalty
  - weak-recording-type penalty

    The practical goal is:

    • keep fewer noisy exemplars
    • prefer clearer single-species song recordings
    • raise the average usefulness of training clips before they ever reach the classifier

    That scoring is now also used during dataset preparation so the exported training set keeps only the top-scoring clips per species. The full curation step is documented separately in:

    • sound-training-curation-flow.md

    1b. Definitive MP3 import¶

    Used to supplement the thin selected sound set with a broader curated local library.

    Base script:

    • import_definitive_mp3_sounds.py

    Current responsibilities:

    • scan Dropbox Definitive MP3
    • normalize filenames such as:
    • Yellowhammer.1.mp3
    • Long Eared Owl.mp3
    • Canadian Goose.mp3
    • map them onto bird_species.common_name
    • apply a small alias table for known naming variants
    • link or copy matched files into:
    • bird-agent/data/sound-training/{species_id}/definitive/...
    • write:
    • definitive_sound_manifest.json
    • definitive_sound_unmatched.json

    1c. Wikimedia Commons audio import¶

    Used to add extra freely licensed training clips from Commons species audio categories.

    Base script:

    • import_commons_bird_sounds.py

    Current responsibilities:

    • query Commons category pages such as:
    • Category:Audio files of <scientific name>
    • Category:Audio files of <common name>
    • fetch file metadata through the MediaWiki API
    • download supported audio formats currently proven in the trainer path:
    • .mp3
    • .wav
    • store them as non-selected training_song rows
    • retry and continue on 429 Too Many Requests responses instead of aborting the whole run

    Important current constraint:

    • Commons often exposes bird audio as .ogg or .flac
    • the current importer intentionally limits itself to formats that fit the present decode/training path cleanly

    2. Normalize selected files¶

    Base script:

    • bird-agent/sync_species_sounds.py

    Current responsibilities:

    • create canonical filenames such as:
    • {slug}_song.mp3
    • {slug}_call.mp3
    • map the selected source rows back into:
    • bird_species.song_audio_url
    • bird_species.call_audio_url
    • keep the selected metadata row marked with is_selected = 1

    3. Audit, retrieval, and backfill¶

    Current scripts:

    • check_bird_sound_ingestion_progress.py
    • query_species_sounds.py
    • backfill_xeno_canto_sound_metadata.py

    Current capabilities:

    • species with selected song
    • species with selected call
    • species with candidate recordings but nothing selected
    • species still missing any usable sound
    • counts by license and quality
    • metadata-first retrieval for local sound queries
    • backfill enrichment for older rows that were ingested before detail-page metadata capture was added

    3b. Build the labeled sound-training dataset¶

    Base script:

    • prepare_sound_training_data.py

    Current responsibilities:

    • read bird_species_sound_sources
    • export per-species training folders
    • include selected-only rows or all ingested rows
    • preserve role separation such as:
    • song
    • call
    • normalize extra training roles into song-like training data:
    • definitive
    • training_song
    • write:
    • species.json
    • sound_training_manifest.json

    Current dataset root:

    • bird-agent/data/sound-training

    Recommended larger network-backed dataset roots:

    • /Volumes/DATA/sound-training
    • /Volumes/DATA/sound-training-all

    4. Loop orchestration¶

    Current scripts:

    • run_next_sound_ingestion.py
    • run_sound_ingestion_loop.py
    • check_sound_ingestion_status.py

    Current behavior:

    • processes 3 species per batch by default
    • waits 20 seconds between batches by default
    • loads XENO_CANTO_API_KEY from bird-agent/.env
    • pauses on operational issues such as a missing API key

    5. Train the sound classifier¶

    Base script:

    • train_bird_sound_classifier.py

    Current behavior:

    1. load species folders from the training dataset
    2. enforce a minimum clip threshold per species
    3. split clips per species into train / val / test
    4. decode MP3s to WAV using:
    5. decode_audio.swift
    6. resample and crop in PyTorch
    7. convert waveforms to log-mel spectrogram features
    8. train a CNN classifier
    9. save the artifact to:
    10. bird-sound-model.pt

    Important current limitation:

    • the sound inference endpoint is not built yet
    • the mobile app can play and upload sound, but cannot yet call a production /identify-bird-sound route

    Environment Notes¶

    The sound ingestion scripts are now env-only for the xeno-canto key:

    • XENO_CANTO_API_KEY

    Recommended .env form:

    XENO_CANTO_API_KEY=your_key_here

    Avoid wrapping the value in quotes.

    Operational Warning¶

    Do not run the bird text-data loop and the sound-ingestion loop at the same time.

    Both write to:

    • birds.db

    Because SQLite allows only one writer at a time, running both loops together can trigger:

    • database is locked

    Retrieval Layer¶

    Current retrieval is metadata-first in:

    • sound_rag.py

    It currently matches on:

    • species
    • song vs call
    • quality
    • country
    • location
    • remarks
    • background species

    Future versions can still add embeddings over:

    • remarks
    • background_species
    • recording_type

    Training Dataset Shape¶

    Expected structure:

    sound-training/
  1/
    species.json
    sound_training_manifest.json
    definitive_sound_manifest.json
    song/
      robin_song.mp3
    call/
      robin_call.mp3
    definitive/
      Robin.mp3
    song/
      robin__xc_123456.mp3

    Each species folder is keyed by bird_species.id.

    The trainer treats these directories as follows:

    • song -> song
    • call -> call
    • definitive -> song-like training data
    • training_song rows are exported into song-like training coverage through the dataset prep flow

    Recommended Storage Pattern¶

    To avoid filling local disk, the current recommended setup is:

    • keep the small canonical app playback files local if needed
    • store the larger training-oriented sound inventory on the Windows network share

    Recommended network paths:

    • /Volumes/DATA/birds/species/sounds
    • /Volumes/DATA/sound-training
    • /Volumes/DATA/sound-training-all

    Typical workflow:

    1. xeno-canto top-up into /Volumes/DATA/birds/species/sounds
    2. optional Commons import into /Volumes/DATA/birds/species/sounds
    3. rebuild training dataset into /Volumes/DATA/sound-training-all
    4. add Dropbox definitive MP3 files into /Volumes/DATA/sound-training-all
    5. train from /Volumes/DATA/sound-training-all

    Current Status¶

    What is already in place:

    • xeno-canto ingestion
    • canonical song/call sync into bird_species
    • metadata-first retrieval
    • app playback
    • species-labeled sound-training dataset generation
    • Dropbox Definitive MP3 import into the training dataset
    • first-pass sound-classifier training
    • saved sound model artifact

    What is not yet in place:

    • backend sound inference helper
    • POST /identify-bird-sound
    • app-side sound identification flow

    Selection Rules¶

    Current default ranking rules:

    1. prefer scientific-name matches over broad common-name matches
    2. prefer permissive licenses over restrictive ones
    3. prefer quality A, then B
    4. prefer clean song for song_audio_url
    5. prefer clean call, alarm call, or flight call for call_audio_url
    6. reject obvious duplicates
    7. reject soundscapes unless they are the only reasonable candidate

    Why This Is Not Pure RAG Yet¶

    The first job is ingestion and normalization:

    • find recordings
    • store them safely
    • keep source metadata

    RAG becomes useful after that:

    • retrieve the best sound examples
    • answer sound-focused questions
    • explain why a clip is a good match

    The current implementation order has become:

    1. source ingestion
    2. metadata table
    3. selected file mapping
    4. metadata backfill
    5. retrieval
    6. optional LLM answer generation
