    Git, Quality, And Release Workflow¶

    Bird and Plant share one repository and one pull-request quality gate. Continuous integration validates changes but does not deploy them: production releases to Hetzner, EAS, TestFlight, or the App Store remain separate, approved operations.

    Frontend Responsibilities¶

    • screen navigation with Expo Router
    • token-authenticated API requests
    • image and sound picking/recording
    • direct Firebase client upload for new prediction media where configured
    • AI suggestion confirmation
    • prediction update flow
    • bird detail gallery rendering
    • guest-aware navigation guards that preserve screen context
    • nearby-alert scheduling and notification-channel controls

    Backend Responsibilities¶

    • JWT authentication
    • protected species, prediction, and upload endpoints
    • image identification
    • sound-ingestion and training-data preparation support scripts
    • joined prediction/species responses
    • syncing media URLs from local datasets into the database
    • resolving stable storage paths such as species/... and predictions/... into signed cloud URLs
    • materializing complete-checklist Stage 3 training examples with deterministic stratified hard negatives
    • resuming long-running Stage 3 backfills from committed checklist boundaries
    • enqueueing idempotent nearby-alert emails for retryable asynchronous delivery

    Storage Model¶

    • bird_species canonical species metadata, default image, song, and call URLs
    • predictions user-created observations and uploaded image/audio URLs
    • bird_detail extra species gallery images used by bird detail views
    • bird_species_sound_sources source-of-truth sound metadata for canonical song / call, extra training_song, and imported definitive clips
    • bird_likelihood_training_examples versioned supervised examples with complete-checklist provenance and positive/negative labels
    • bird_likelihood_models versioned model metadata, evaluation metrics, and artifact references
    • notification_outbox idempotent nearby-alert email work items with retry and provider-acceptance state

    Media Strategy¶

    • default species images: species/{speciesId}/images/default/...
    • extra gallery images: species/{speciesId}/images/gallery/...
    • species sounds: species/{speciesId}/audio/song/... species/{speciesId}/audio/call/...
    • customer uploads: predictions/uploads/... predictions/audio/...

    Local /uploads/... media still exists as source material and fallback, but migrated app responses are signed Firebase/GCS URLs.

    The larger sound-training datasets and intermediate model artifacts can also live outside the app media buckets, for example on /Volumes/DATA during local training.

    AI Strategy¶

    • inference is server-side
    • the backend can load either:
    • a reference-index artifact
    • a classifier artifact
    • sound training is now a multi-step pipeline:
    • ingest and top up clips
    • assemble a curated per-species dataset
    • train and save a .pt artifact for backend inference
    • mobile clients receive ranked predictions and confirm the final species choice
    • contextual likelihood training uses complete checklist events so present and absent labels share the same observation protocol
    • hard negatives are selected deterministically across local recency, local seasonality, and regional seasonality strata
    • long-running materialization jobs expose phase-level timings and resume only from fully committed checklist boundaries
