    Sound Training Curation Flow¶

    This page covers the quality-filtering step that sits between sound ingestion and model training.

    Its purpose is simple:

    • score each candidate clip
    • keep only the strongest examples per species
    • export a cleaner training dataset

    Key script:

    • bird-agent/ai/prepare_sound_training_data.py

    Why This Exists¶

    After the xeno-canto top-up work, the project had a deeper sound dataset, but the training pool still mixed:

    • strong clean song recordings
    • weaker or noisy song recordings
    • occasional call-like or mixed-context examples

    That meant better clips were being added on top of poorer ones instead of replacing them in the exported training set.

    The curation step fixes that by making dataset preparation score-aware.

    Five-Step Flow¶

    1. Score every candidate clip¶

    Each ingested sound row gets a training-quality score based on metadata already stored in bird_species_sound_sources.

    Current inputs include:

    • quality_grade
    • audio_role
    • recording_type
    • duration_seconds
    • remarks
    • background_species
    • is_selected

    Broad intent:

    • reward cleaner song-like recordings
    • penalize noisy, distant, overlapping, or weak-context recordings

    2. Preserve the quality signal¶

    The quality distinction is not left only in downloader logic.

    During dataset preparation, every exported manifest item now includes:

    • training_quality_score

    That makes it visible which files were considered strongest for model training.

    3. Rank clips per species¶

    Before files are copied into the dataset, each species' valid source rows are sorted by score.

    Higher-ranked clips tend to be:

    • definitive, song, or training_song
    • A or B quality
    • moderate duration
    • free of background species
    • free of noisy remarks

    Lower-ranked clips tend to be:

    • call
    • long or awkward duration
    • noisy or overlapping
    • marked with background species

    4. Export only the top clips¶

    prepare_sound_training_data.py now keeps only the top-scoring clips per species.

    Default behavior:

    • --max-clips-per-species 5

    That means the exported dataset is no longer "all available clips." It is now a curated subset intended to be more learnable.

    Inspect the ranking directly¶

    You can also inspect the current top-ranked clips without exporting files by using:

    • --report-only

    That prints a JSON report showing, per species:

    • selected clip ids
    • audio roles
    • source recording ids
    • quality metadata
    • training_quality_score

    This is useful when you want to audit whether the heuristic ranking is actually choosing the clips you would expect.

    5. Rebuild and retrain¶

    Once the curated dataset is exported:

    1. retrain the sound classifier
    2. compare against the previous baseline
    3. judge whether cleaner clips helped more than raw clip count alone

    Visual Flow¶

    flowchart TD
    A["All ingested sound rows<br/>bird_species_sound_sources"] --> B["Resolve storage paths<br/>keep only files that exist"]
    B --> C["Score each clip<br/>quality<br/>role<br/>duration<br/>remarks<br/>background species"]
    C --> D["Rank clips within each species"]
    D --> E["Keep top N clips per species<br/>default N = 5"]
    E --> F["Write curated species folders<br/>species.json + manifest"]
    F --> G["Train sound classifier on cleaner inputs"]

    Current Scoring Direction¶

    The current scoring is intentionally heuristic rather than ML-driven.

    It prefers:

    • definitive
    • song
    • training_song
    • quality A and B
    • roughly 5 to 20 second clips

    It penalizes:

    • call
    • alarm and flight call
    • subsong
    • background species
    • noisy remarks like wind, traffic, distant, overlap, or low-volume style notes

    Practical Effect¶

    This changes dataset preparation from:

    • export everything valid

    to:

    • export only the strongest clips per species

    That should make the training set:

    • smaller
    • cleaner
    • easier to reason about
    • easier to compare across experiments

    Example Command¶

    cd <path-to-bird-platform>/bird-agent
.venv/bin/python -m ai.prepare_sound_training_data \
  --dataset-root /Volumes/DATA/sound-training-all \
  --uploads-dir /Volumes/DATA \
  --include-unselected \
  --mode copy \
  --max-clips-per-species 5

    Example report command:

    cd <path-to-bird-platform>/bird-agent
.venv/bin/python -m ai.prepare_sound_training_data \
  --uploads-dir /Volumes/DATA \
  --include-unselected \
  --max-clips-per-species 5 \
  --report-only \
  --report-species-limit 20
