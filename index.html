    Spark Birds¶

    Spark Birds is a production mobile birding application available on the Apple App Store. The system is built with Expo, React Native, FastAPI, PostgreSQL, and Firebase/GCS-backed authentication and media storage. Its AI architecture combines computer vision, retrieval-augmented generation, ecological machine learning, and data-engineering pipelines with conventional transactional application services.

    The current platform combines:

    • a protected REST API with layered backend services
    • a mobile client for browsing, prediction, community, analytics, and settings flows
    • a browser-based admin surface for moderation, support, species media, and promotions
    • a server-side image-identification pipeline
    • a retrieval-augmented AI Bird Log assistant grounded in species knowledge
    • a contextual bird-likelihood ML pipeline built from eBird/EBD evidence
    • spatially clustered nearby-bird alerts with per-user schedules, channel preferences, and durable email delivery
    • synced species galleries, calls, and songs
    • signed cloud media URLs returned by the backend
    • Firebase client-storage support for new prediction image and audio uploads
    • backend-driven promotions and operational workflow controls

    Core Features¶

    • species catalogue and detail pages
    • prediction creation and editing
    • AI image identification with ranked suggestions
    • retrieval-augmented bird questions through the AI Bird Log
    • contextual bird-likelihood modelling with complete-checklist cohorts, deterministic hard-negative sampling, and reproducible model evaluation
    • resumable Stage 3 data backfills with checklist-boundary checkpoints and phase-level timing metrics
    • scheduled nearby-bird alerts using spatial clustering, Redis caching, species-level deduplication, and an idempotent email outbox
    • community sharing, ratings, reactions, and comments
    • moderation and support ticket workflows
    • backend-driven promotion cards after login
    • analytics over stored predictions
    • extra gallery images per species via bird_detail
    • species songs and calls resolved to signed Firebase/GCS URLs
    • prediction audio recording, upload, update, and playback

    Technology Stack¶

    Layer Technology
    Mobile frontend Expo, React Native, TypeScript
    Browser admin React, TypeScript, Vite
    Navigation Expo Router
    Backend API FastAPI
    Database PostgreSQL
    Authentication Firebase Auth with bearer-token verification
    AI and ML PyTorch, torchvision, timm, LightGBM, semantic retrieval/RAG
    Media storage Firebase/GCS primary, backend /uploads fallback/source storage
    Docs MkDocs Material

    Production And Model Notes¶

    • image inference is server-side, not on-device
    • core product workflows now run against PostgreSQL in production
    • some ingestion and legacy helper tooling can still reference SQLite-oriented assets during the wider migration period
    • extra species images are still sourced from /uploads/birds/others_images locally, but migrated media is returned from signed Firebase/GCS URLs
    • bird_species.song_audio_url and bird_species.call_audio_url currently point to the same canonical _song.mp3 file when only one source recording exists
    • xeno-canto import tooling is now part of the repo for filling missing species sounds
