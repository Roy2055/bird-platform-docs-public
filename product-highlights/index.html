    Product Highlights¶

    This page summarises the principal product, AI, data, and operational capabilities of the production Spark Birds platform.

    Platform Summary¶

    Spark Birds is a professional, App Store-launched birding product that combines:

    • a mobile-first Expo / React Native application
    • a FastAPI backend
    • PostgreSQL-backed product workflows
    • Firebase authentication and media storage
    • AI-assisted visual identification, grounded bird Q&A, contextual likelihood ranking, and model-training pipelines
    • community moderation, support, and admin operations tooling

    System Scope¶

    The platform is maintained as one integrated product system spanning:

    • consumer mobile UX
    • admin and moderation operations tooling
    • AI-assisted user workflows
    • production backend architecture and deployment controls
    • documented deployment and operational controls

    This shared architecture keeps mobile contracts, AI inference, data pipelines, moderation, administration, and production operations aligned while retaining clear component boundaries.

    User-Facing Capabilities¶

    Bird Discovery And Reference¶

    • searchable species catalogue
    • species detail pages with gallery images
    • song and call playback
    • lightweight thumbnail-first media handling for larger galleries
    • signed cloud media URLs returned by the backend

    Prediction Workflows¶

    • create and update prediction flows
    • image-based bird identification with ranked suggestions
    • audio attachment support
    • location-aware notes and metadata
    • analytics over stored sightings and prediction activity
    • cursor-based pagination and infinite-scroll support for larger saved-sightings histories

    Community Features¶

    • shared community predictions
    • grouped user feeds
    • star ratings, reactions, and comments
    • owner controls for community content
    • reporting and blocking workflows for user safety
    • larger-screen layout adjustments so iPad presentation preserves image subjects more reliably across detail and community views

    Support And Safety¶

    • private user support ticket threads
    • community report acknowledgements and updates surfaced in-app
    • closed-case handling for resolved tickets
    • user follow-up loop after moderation review
    • direct admin closure from the review workflow when appropriate

    Promotions And Engagement¶

    Bird Platform now includes a backend-driven promotions system that can:

    • schedule promotional cards after login
    • control repeat frequency per user
    • display bundled or remote artwork
    • support CTA-driven promos or image-only advert cards
    • be managed through a browser-based admin workspace

    This is implemented as a product capability rather than a hard-coded marketing banner, which makes it suitable for:

    • feature launches
    • onboarding nudges
    • engagement experiments
    • internal campaign management

    High-level promo workflow:

    flowchart LR
    A["Admin promo setup"] --> B["Backend promotion record"]
    B --> C["Mobile app checks active promo"]
    C --> D["Eligible user sees promo card"]
    D --> E["Show / dismiss / click events recorded"]

    The underlying product design separates:

    • the promo definition itself
    • the per-user interaction and cooldown state

    This separates campaign configuration from per-user delivery state and keeps engagement behaviour auditable and server-controlled.

    Admin And Operations Tooling¶

    The browser-based admin web supports:

    • species image ordering and default-image selection
    • canonical sound quality management
    • support-ticket handling
    • moderation workflow management
    • promotions creation, editing, previewing, activation, and deletion

    These capabilities provide the operational layer required to administer the released application, including:

    • operational tooling
    • workflow controls
    • audit-friendly back-office capability

    AI And Machine-Learning Architecture¶

    AI is integrated into user-facing and operational workflows rather than being treated as a standalone experiment. The platform covers computer vision, retrieval-augmented generation, contextual likelihood ranking, training-data engineering, model evaluation, model registries, and guarded serving integration.

    AI-Assisted Identification¶

    • backend-hosted bird image inference
    • ranked species suggestion flows
    • transfer-learning architecture using PyTorch, torchvision, and timm
    • confidence-ranked results integrated into the mobile prediction workflow
    • media moderation-aware save workflows
    • AI-forward product messaging and bird-detail/local-sightings phrasing that better explains recency and evidence windows to end users

    Context-Aware Bird Likelihood¶

    The Stage 3 likelihood pipeline adds ecological context to species ranking instead of relying on image evidence alone. Its current engineering foundation includes:

    • bulk eBird/EBD observation ingestion into a dedicated raw evidence layer
    • complete-checklist-aware positive and negative training examples
    • deterministic whole-checklist sampling that avoids splitting one observation event across dataset boundaries
    • stratified hard-negative selection across recent-local, seasonal-local, and seasonal-regional evidence
    • canonical species resolution across historical and current common-name variants
    • temporal and geographic metadata features used alongside species identity
    • geospatial reference-layer preparation for richer habitat and location context
    • LightGBM and logistic-regression training support
    • validation and linkage-coverage gates before promotion
    • versioned model artifacts and registry-backed runtime loading
    • guarded runtime feature projection so serving follows the training feature contract
    • resumable backfills that checkpoint only after a complete checklist has been committed
    • phase-level timing and timeout metrics for evidence queries, candidate selection, and writes

    This is an end-to-end ML lifecycle: evidence ingestion, label construction, leakage-aware cohort design, hard-negative sampling, feature engineering, model comparison, evaluation gates, artifact versioning, and controlled inference integration. Stage 3 remains promotion-gated so measured staging quality must be accepted before it replaces a live scoring path.

    Recent Application Improvements¶

    Recent app-level improvements reflected in the current App Store release line include:

    • pooled PostgreSQL connection reuse in the main compatibility layer
    • paginated sightings/predictions retrieval for more scalable mobile history browsing
    • infinite-scroll loading on the mobile sightings list
    • iPad-specific image-fit improvements for bird detail and community screens
    • stronger bird-detail audio lifecycle guarding around native player teardown
    • guest-mode navigation that keeps users in context and presents sign-in prompts without unnecessary screen transitions
    • clearer nearby-alert controls with live interval labels, a sightings-period slider, channel preferences, and safer handling of deleted locations
    • Stage 3 contextual bird-likelihood foundations spanning EBD ingestion, complete-checklist labels, stratified hard negatives, canonical species linkage, contextual features, resumable backfills, LightGBM training, evaluation gates, and registry-backed inference

    Bird Q&A / Retrieval¶

    • an in-app AI Bird Log assistant for natural-language bird questions
    • retrieval-augmented generation backed by species metadata and semantic embeddings
    • provider abstraction supporting local and configured hosted-model paths
    • retrieval ranking that grounds generated answers in platform bird knowledge instead of relying only on unconstrained model recall
    • graceful fallback behaviour when a configured AI provider is unavailable

    Intelligent Nearby Alerts¶

    • per-user alert locations, radii, recency windows, and check intervals
    • geographic clustering so nearby users share eBird lookups instead of producing one external request per user
    • Redis caching for repeated cluster queries
    • durable per-user species deduplication to reduce repeated alerts
    • user-controlled push and email notification preferences
    • multi-channel push, email, and webhook dispatch
    • an idempotent PostgreSQL email outbox with retry scheduling, attempt history, safe error classification, and provider-acceptance tracking

    The alert system deliberately uses data-driven scheduling and spatial optimisation rather than machine learning. AI is reserved for problems where learned ranking, classification, or grounded language generation provides measurable value; deterministic mechanisms remain in control of scheduling, deduplication, retries, and delivery state.

    Data Engineering Support¶

    • sound ingestion and curation tooling
    • image ingestion workflows
    • migration-aware media handling
    • controlled schema evolution through Alembic and structured backend layers

    Architecture And Delivery Strengths¶

    The platform applies the following engineering patterns:

    • clear backend layering: router -> service -> repository
    • dedicated admin surface separate from the mobile app
    • PostgreSQL-backed workflow state for moderation, support, and promotions
    • Firebase integration for auth and media
    • environment-driven operational controls
    • suitable Hetzner deployment with explicit runbooks and validation steps
