    Git Workflow¶

    This project uses a simple branch flow:

    • feature/... for active work
    • dev as the integration branch
    • main as the release branch

    The recommended path is:

    feature branch -> dev -> main

    Standard Flow¶

    1. Start from dev¶

    cd <path-to-bird-platform>
git checkout dev
git pull origin dev

    2. Create a feature branch¶

    git checkout -b feature/your-feature-name

    Examples:

    git checkout -b feature/prediction-audio
git checkout -b feature/firebase-client-storage
git checkout -b feature/bird-detail-notes

    3. Make your changes¶

    Work normally in the feature branch.

    4. Review before committing¶

    git status
git diff

    If relevant, also run checks such as:

    cd bird-app
./node_modules/.bin/tsc --noEmit

    or:

    cd bird-agent
uv run python main.py

    5. Commit the feature branch¶

    git add .
git commit -m "feat: short description of the change"

    Use the commit guide in contributing.md for message style.

    6. Push the feature branch¶

    git push -u origin feature/your-feature-name

    Merge into dev¶

    When the feature is ready:

    git checkout dev
git pull origin dev
git merge --no-ff feature/your-feature-name -m "Merge feature/your-feature-name into dev"
git push origin dev

    Test on dev before promoting to main.

    Merge dev into main¶

    When dev is stable:

    git checkout main
git pull origin main
git merge --no-ff dev -m "Merge dev into main"
git push origin main

    Delete the feature branch¶

    After the branch has been merged:

    git branch -d feature/your-feature-name
git push origin --delete feature/your-feature-name

    If Git says the branch is not fully merged, only force delete if you are sure:

    git branch -D feature/your-feature-name

    Quick Checklist¶

    Before coding¶

    • switch to dev
    • pull the latest origin/dev
    • create a new feature/... branch

    Before committing¶

    • run git status
    • review git diff
    • run the relevant checks for app/backend/docs

    Before merging to dev¶

    • commit everything on the feature branch
    • push the feature branch
    • switch to dev
    • pull origin/dev
    • merge feature into dev

    Before merging to main¶

    • confirm dev is stable
    • switch to main
    • pull origin/main
    • merge dev into main
    • push origin/main

    After release¶

    • optionally merge main back into dev if extra cleanup happened only on main
    • delete the old feature branch

    Short Solo-Developer Version¶

    git checkout dev
git pull origin dev
git checkout -b feature/my-change

# make changes

git add .
git commit -m "feat: my change"
git push -u origin feature/my-change

git checkout dev
git pull origin dev
git merge --no-ff feature/my-change -m "Merge feature/my-change into dev"
git push origin dev

git checkout main
git pull origin main
git merge --no-ff dev -m "Merge dev into main"
git push origin main

    Notes for This Repo¶

    • Start new work from dev, not main
    • Use non-interactive Git commands where possible
    • Prefer git merge ... -m "..." to avoid getting stuck in a terminal editor
    • Keep generated local reports out of commits unless they are intentionally part of documentation or reproducibility
