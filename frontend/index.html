    Frontend App Structure¶

    The frontend is built with Expo, React Native, TypeScript, and Expo Router.

    There is also a separate browser-based admin client in admin-web/ for Windows/macOS browser use.

    In coding terms, the browser admin is now the official admin surface. The older in-app admin review screens have been de-scoped from the mobile app.

    For screen-flow diagrams, use the split UI map pages:

    • Navigation And Core Screens
    • Bird Detail View
    • Prediction Create And Update
    • Analytics And Community

    Main Screens¶

    Screen Purpose
    Species Browse bird species
    Bird Detail Show species details or prediction detail, including gallery images
    Predictions Show saved predictions and navigate into detail/update
    Community Show shared predictions grouped by user, with ratings, reactions, comments, and community detail navigation
    Add Prediction Create a new prediction with AI, location, image, audio, and notes
    Update Prediction Edit an existing prediction, including replacing/removing audio
    Analytics Show summary charts, counts, and hotspot-focused map pins
    AI Bird Log Configure nearby-alert location, radius, interval, sightings period, and notification channels
    Settings Theme mode, support, moderation updates, and account deletion
    Admin Web Manage species image ordering, image quality scoring, and default-image selection in a browser
    Promotions Backend-driven promotional cards that appear after login based on timing, priority, and per-user state

    Bird Detail Behavior¶

    • from Species: loads by species_id
    • from Predictions: loads by prediction_id
    • from Community: loads by prediction_id through the community-safe detail endpoint
    • prefers a prediction image when one exists
    • falls back to the species default image
    • shows additional species images from additional_image_urls, in backend-provided bird_detail.display_order
    • uses gallery thumbnails first for heavy species image sets, then opens the full detail image when needed
    • plays prediction-attached audio when audio_url exists
    • species song preview no longer preloads on screen open; first tap loads and plays the preview
    • species song preview auto-stops after the configured preview window
    • when opened from Community, the back action returns to Community instead of Predictions

    Add / Update Prediction UX¶

    • image stays anchored at the top of the form
    • AI suggestion list appears below the species picker
    • selecting an AI suggestion collapses the suggestion list
    • location search uses the shared LocationSearch component
    • Number seen uses a - [value] + stepper
    • the empty image frame uses a centered icon placeholder until a species or photo is selected
    • Add Prediction supports recording audio or choosing an audio file
    • Update Prediction supports recording, choosing, previewing, and removing audio
    • prediction cards support deletion
    • prediction cards expose a top-right share control for community sharing
    • update prediction uses the same Number seen stepper pattern
    • update prediction no longer silently carries the old custom image across species changes
    • customer image moderation is asynchronous, so a save with a newly selected image may take a short moment before the prediction is created or updated
    • the image picker helper under the add-prediction image tile uses a compact left-aligned Choose label with icon
    • iPhone keyboard support now uses a shared accessory with up, down, and tick actions on key form fields
    • tapping Identify dismisses keyboard focus before the AI request starts

    Community UX¶

    • shared predictions are grouped by user
    • the signed-in user group is shown first
    • other users are ordered by highest average overall community rating, descending
    • each user group is collapsed to the latest shared card by default
    • tapping the chevron expands or collapses the rest of that user's cards
    • star-rating taps update the local card immediately without forcing a full feed reorder
    • broader feed ordering is refreshed on screen focus rather than during the rating tap itself
    • group headers show:
    • display name
    • {x} Birds sighted
    • Avg overall rating as stars
    • each card supports:
    • star rating
    • thumbs up/down reactions for non-owners only
    • comment count and a comments sheet
    • owner-only Delete action, which unshares the item from community but keeps the local prediction
    • non-owner report/block actions through an overflow menu
    • deleting the underlying prediction from Predictions removes it both locally and from Community

    Community Comments¶

    • the comments icon opens a bottom sheet from the community card
    • the comment input auto-focuses on open
    • the sheet uses safe-area-aware sizing and keyboard avoidance for phone use
    • comments are listed newest first
    • adding a comment updates the local count immediately and persists centrally through the backend
    • long-press on another user’s comment exposes report/block actions

    Settings, Support, And Safety UX¶

    • Settings now includes:
    • light / dark mode switching
    • Support messages for direct user-to-admin contact
    • Moderation case updates for report acknowledgements, admin updates, and user follow-up after a decision stage
    • account deletion
    • guest mode shows an inline login/upgrade path
    • guest-only restrictions are intercepted before navigation, keeping the user on the current bird-list screen while presenting a contextual sign-in prompt
    • guest sessions label the account action as Sign in rather than Log out
    • admin users see a handoff note that operational admin work now happens in the browser-based admin web
    • support tickets can be closed by the user and then move to Closed Cases instead of being deleted
    • reply actions now use clearer Reply wording in the support/moderation UI
    • resend-verification and related auth errors should fall back to user-friendly generic error text when no specific safe message is available

    Promotions UX¶

    • promotions are backend-driven rather than hard-coded into the app
    • a promotion can be a CTA-driven card or a full-image advert card
    • display timing is controlled per promotion and can override environment defaults
    • repeat frequency is tracked per user through backend state
    • image-based advert cards can be shown as full-card creatives with only a dismiss control
    • promo configuration is now managed operationally from the browser-based admin web

    Bird Questions¶

    • the Bird List header exposes a left-side bird icon
    • tapping it opens a top-drop question panel
    • the question input auto-focuses on open
    • the answer block can show the top matched bird image beside the answer text
    • the panel calls the backend bird-question endpoint and displays both the answer and best matching birds

    Analytics Map Behavior¶

    • the map initially zooms to the densest cluster of prediction pins
    • a Show all pins control lets the user jump back to the full extent
    • map access from AI Bird Log remains on the current screen and prompts for an alert location when none has been saved
    • deleting an alert location clears the persisted coordinates as well as the visible field, preventing a removed location from reappearing after navigation
    • an empty required location field receives a green themed border so the next action is visually clear

    Nearby Alert Controls¶

    • search radius, check interval, and sightings period use themed sliders
    • the selected interval and sightings-period values are displayed directly in their labels
    • supported check intervals include short polling choices through monthly checks
    • push and email channels use independent checkbox-style preferences
    • notification preferences and scheduling values are persisted through the backend alert profile

    API Integration¶

    The app uses bearer tokens for protected routes and converts backend media paths into full URLs with getMediaUri(...).

    For new prediction media, the frontend now prefers direct Firebase client uploads and falls back to backend upload endpoints when Firebase client configuration is unavailable.

    Prediction-image moderation flow:

    • upload selected image to Firebase Storage
    • poll backend moderation status
    • save the prediction only after the image reaches approved
    • show rejection/error feedback when moderation fails

    The admin website uses the backend admin endpoints directly:

    • GET /admin/species
    • GET /admin/species/{species_id}/images
    • PATCH /admin/species/{species_id}/default-image
    • PATCH /admin/species/{species_id}/image-order

    The admin image manager now also exposes:

    • image_quality as a compact per-image numeric control
    • song_audio_quality and call_audio_quality as canonical A-E selectors
    • Remove / Restore controls for hiding gallery rows without deleting them

    Blank or invalid image-quality values default back to 5.

    There are now two practical admin-web modes:

    1. local/dev mode
    2. deployed Hetzner mode

    Local/dev mode expects:

    • the Vite admin-web URL in the browser, for example http://<mac-ip>:4173
    • the FastAPI backend URL inside the login form, for example http://<mac-ip>:8000

    Current deployed production shape:

    • https://admin.clevermatrixdevelopments.co.uk serves the built admin-web/dist
    • https://api.clevermatrixdevelopments.co.uk serves the FastAPI backend
    • the login screen is prefilled with the live API base URL

    This keeps the admin UI and API on separate hostnames while the backend/database remains the source of truth.

    Media Rendering¶

    • customer prediction image if available
    • otherwise species default image
    • gallery thumbnails for extra species images
    • gallery thumbnails exclude hidden rows where display_order = 999
    • richer image metadata can still be surfaced from additional_image_items even when an image is hidden from the gallery strip
    • species audio buttons using song_audio_url and call_audio_url
    • species preview audio duration is controlled by the Expo config/env setting rather than hard-coded timing
    • prediction audio playback using audio_url
    • Firebase/GCS signed URLs are treated as first-class image/audio sources
    • SafeImage resets internal loading/error state when the image source changes, which avoids stale blank tiles after prediction updates or uploads
    • the browser-based admin site updates default image selection and gallery ordering without relying on filename priority rules
