    Bird Data Collection Pipeline¶

    This page shows the end-to-end retrieval, augmentation, and generation flow used by the species metadata completion agent in bird-agent/bird_data_collection_agent.py, plus the one-at-a-time loop runners in:

    • bird-agent/run_next_bird_data_collection.py
    • bird-agent/run_bird_data_collection_loop.py

    Visual Flow¶

    Overview¶

    flowchart TD A["60-second loop run_bird_data_collection_loop.py"] --> B["Run one species run_next_bird_data_collection.py"] B --> C["Select next eligible row no_of_cleansing_passes = 0"] C --> D["Retrieve trusted source text RSPB, eBird, BTO, All About Birds Wikipedia fallback"] D --> E["Augment prompt species data + blank fields + source text"] E --> F["Generate candidate JSON OpenAI extraction step"] F --> G["Clean and validate fields"] G --> H["Go / no-go gate"] H -->|Write| I["Save only blank fields increment no_of_cleansing_passes"] H -->|Ignore| J["Mark ignored set no_of_cleansing_passes = 100"] I --> K["Update loop state"] J --> K["Update loop state"]

    Decision Gate¶

    flowchart TD A["Validated candidate fields"] --> B{"Trusted non-Wikipedia source?"} B -->|No| C["Ignore source quality too weak"] B -->|Yes| D{"Enough validated fields survive?"} D -->|No| E["Ignore row is too thin"] D -->|Yes| F{"More than 2 strong factual fields?"} F -->|No| G["Ignore not enough strong facts"] F -->|Yes| H["Write save missing fields only"] H --> I["increment no_of_cleansing_passes += 1"] C --> J["set no_of_cleansing_passes = 100"] E --> J G --> J

    Step Summary¶

    1. The loop runner wakes every 60 seconds and starts one safe processing pass.
    2. The selector loads the next bird_species row where no_of_cleansing_passes = 0 and at least one target field is blank.
    3. The agent gathers trusted source text, preferring RSPB, eBird, BTO, and All About Birds, with Wikipedia only as fallback context.
    4. The OpenAI extraction step turns that context into candidate JSON field values.
    5. Cleaning and validation remove placeholders, wrong-shaped values, and weak field mappings.
    6. The gate decides write or ignore.
    7. A successful write fills only still-blank columns and increments no_of_cleansing_passes.
    8. An ignored row is marked with no_of_cleansing_passes = 100 so it is not selected again.

    Loop orchestration¶

    • bird-agent/run_next_bird_data_collection.py
    • loads one eligible species
    • prevents overlap with a lock file
    • pauses only on true operational issues such as AI unavailability
    • bird-agent/run_bird_data_collection_loop.py
    • repeats run_once() every 60 seconds by default
    • processes one species at a time

    Audit Trail¶

    The agent uses bird_species.no_of_cleansing_passes as the selection and audit column:

    • 0 row is still eligible for processing
    • 1, 2, ... row was written successfully and should not be reselected
    • 100 row was reviewed and intentionally ignored, and should not be reselected

    Current Loop Behavior¶

    The safer loop mode is:

    cd <path-to-bird-platform>/bird-agent
.venv/bin/python run_bird_data_collection_loop.py

    Key behavior:

    • processes one species per iteration
    • waits 60 seconds between iterations by default
    • stops if there are no eligible species left
    • stops if a true operational issue occurs
    • does not pause the whole loop just because one species times out
