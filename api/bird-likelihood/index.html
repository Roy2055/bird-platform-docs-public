    Bird Likelihood API¶

    GET /bird-likelihood¶

    Returns a bird likelihood score for seeing a species near a chosen location.

    This endpoint combines:

    • recent eBird sightings
    • recent Spark Birds community sightings
    • the authenticated user's own sightings
    • distance to nearby evidence
    • seasonal suitability from the species record
    • historical species-month matches stored in local observation history

    The default implementation is now the Stage 2 statistical model described in the internal likelihood design notes. It remains explainable, but it uses smoothed probabilities instead of only hard thresholds.

    Authentication¶

    This endpoint is protected and requires:

    Authorization: Bearer <token>

    Query Parameters¶

    • species
    • required
    • common species name such as European Robin
    • lat
    • required
    • latitude to evaluate
    • lng
    • required
    • longitude to evaluate
    • radius_km
    • optional
    • defaults to 10
    • maximum 100
    • model_stage
    • optional
    • defaults to stage_2_statistical
    • accepts:
      • stage_2_statistical
      • stage_1_rule_based

    Example Request¶

    GET /bird-likelihood?species=European%20Robin&lat=51.5074&lng=-0.1278&radius_km=10&model_stage=stage_2_statistical
Authorization: Bearer <token>

    Example Response¶

    {
  "species": "European Robin",
  "likelihood_label": "Very High",
  "likelihood_score": 0.84,
  "total_score": 84,
  "recent_sightings_count": 23,
  "nearest_sighting_km": 0.8,
  "last_seen_days_ago": 1,
  "reason": "Seen 23 times within 10km in the last 7 days, with strong recent local evidence.",
  "model_stage": "stage_2_statistical",
  "ebird_sightings_count": 18,
  "community_sightings_count": 3,
  "user_sightings_count": 2,
  "score_breakdown": {
    "recent_probability": 0.979,
    "recency_probability": 0.895,
    "distance_probability": 0.787,
    "season_probability": 1.0,
    "historical_month_probability": 0.722,
    "source_support_probability": 1.0
  }
}

    Response Fields¶

    • species
    • normalized species name used for scoring
    • likelihood_label
    • one of Low, Medium, High, Very High
    • likelihood_score
    • normalized 0.0-1.0 score for app display
    • total_score
    • raw 0-100 Stage 1 score
    • recent_sightings_count
    • total matched nearby evidence count across supported sources
    • nearest_sighting_km
    • closest matching sighting distance if evidence exists
    • last_seen_days_ago
    • age in whole days of the freshest evidence if available
    • reason
    • short explanation suitable for app UX
    • model_stage
    • current scoring implementation identifier
    • ebird_sightings_count
    • matched evidence rows from recent eBird observations
    • community_sightings_count
    • matched shared community predictions
    • user_sightings_count
    • matched predictions created by the authenticated user
    • score_breakdown
    • component probabilities used to build the final model output

    Model Stages¶

    Default: Stage 2 statistical model¶

    Stage 2 is still explainable, but it is no longer purely threshold-based.

    It combines smoothed probabilities from:

    • recent local sighting volume
    • freshness of evidence
    • proximity of the nearest sighting
    • species seasonal fit
    • historical local month-matched observations
    • support from eBird, community, and user evidence sources

    This gives a more realistic probability surface than Stage 1, especially for:

    • sparse data
    • seasonal species
    • species with moderate but consistent historical local presence

    Baseline: Stage 1 rule-based model¶

    Stage 1 remains available for comparison:

    model_stage=stage_1_rule_based

    That version uses fixed explainable score buckets rather than smoothed probabilities.

    Label Mapping¶

    Both model stages currently map the final 0-100 score to labels like this:

    Score Label
    0-25 Low
    26-50 Medium
    51-75 High
    76-100 Very High

    Intended Use¶

    This endpoint is appropriate for:

    • surfacing "what am I likely to see here?" suggestions in the app
    • driving nearby bird recommendation UI
    • providing a baseline before Stage 2 statistical modelling
    • debugging evidence quality through score_breakdown

    It is not yet the final machine-learned scientific occurrence model. That comes later in Stage 3.
