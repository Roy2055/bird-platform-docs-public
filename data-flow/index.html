    Data Flow¶

    Login Flow¶

    sequenceDiagram participant User participant App participant API User->>App: Enter username/password App->>API: POST /token API-->>App: JWT access token App->>App: Store token for future requests

    Add Prediction Flow¶

    sequenceDiagram participant App participant API participant Cloud participant DB App->>App: Pick image App->>App: Optionally record or choose audio App->>Cloud: Upload prediction image/audio directly when Firebase client config exists App->>API: POST /upload-image or /upload-sound if falling back API->>Cloud: Upload customer media to Firebase / GCS API-->>App: Return image_url / audio_url App->>API: POST /predictions API->>DB: Insert prediction API-->>App: Return joined prediction payload

    AI Identification Flow¶

    sequenceDiagram participant App participant API participant AI participant DB App->>API: POST /identify-bird-image API->>AI: Load model + preprocess image AI->>DB: Map class ids to bird species metadata AI-->>API: Ranked predictions API-->>App: predictions[] + model metadata App->>App: User confirms one suggestion

    Bird Detail Flow¶

    flowchart TD App["Bird detail screen"] --> API["GET /bird-species/{id} or /predictions/{id}"] API --> DB["PostgreSQL"] DB --> Species["bird_species"] DB --> Detail["bird_detail
    ordered gallery + provenance"] API --> Media["Signed Firebase / GCS media URLs"] Media --> App

    Sound Ingestion And Training Flow¶

    flowchart TD XC["download_xeno_canto_sounds.py
    selected song/call + training top-up"] --> DB["bird_species_sound_sources"] Definitive["import_definitive_mp3_sounds.py"] --> Dataset["prepare_sound_training_data.py
    score and keep top clips per species"] DB --> Dataset Dataset --> TrainingSet["/Volumes/DATA/sound-training-all
    curated per-species folders"] TrainingSet --> Train["train_bird_sound_classifier.py"] Train --> Artifact["bird-sound-model.pt"] DB --> Canonical["bird_species.song_audio_url / call_audio_url"]

    Canonical app playback still flows through bird_species.song_audio_url and bird_species.call_audio_url, but training now works from the broader bird_species_sound_sources metadata table plus curated exports.

    Firebase Migration Flow¶

    flowchart TD Local["Legacy /uploads paths + training media"] --> Migrate["migrate_media_to_firebase.py"] Migrate --> Bucket["Firebase / GCS bucket"] Migrate --> Manifest["firebase_media_manifest.json"] Local --> Cleanup["cleanup_media_storage_paths.py"] Manifest --> Cleanup Cleanup --> DB["PostgreSQL stores species/... and predictions/..."] DB --> API["FastAPI resolves signed URLs"]

    Contextual Likelihood Training Flow¶

    flowchart LR Raw["Raw eBird/EBD observations"] --> Cohort["Approved complete checklists"] Cohort --> Positive["Reported species
    positive labels"] Cohort --> Negative["Absent but ecologically plausible species
    stratified hard negatives"] Positive --> Features["Versioned feature materialization"] Negative --> Features Features --> Split["Checklist-safe train / validation / test split"] Split --> Train["Logistic regression and LightGBM evaluation"] Train --> Registry["Versioned artifact and model registry"]

    Whole checklists are selected through stable hash buckets, preventing a row limit from splitting one observation event. Long-running materialization can resume from checklist-boundary commits, while phase-level timings identify whether source loading, ecological evidence, candidate selection, or writes dominate runtime.

    Nearby Alert Delivery Flow¶

    sequenceDiagram participant Worker participant DB participant Outbox participant EmailProvider Worker->>DB: Persist newly discovered species Worker->>Outbox: Enqueue idempotent email event Outbox->>EmailProvider: Attempt due delivery EmailProvider-->>Outbox: Accepted or classified failure Outbox->>DB: Store provider id or schedule retry

    Push, email, and webhook preferences are stored per user. Email delivery uses a durable outbox so a transient provider failure does not discard the notification event, while deduplication keys prevent the same discovery from being enqueued twice.
