    Artifacts, Embeddings, And Classification Flows¶

    This page explains how the platform uses:

    • classifier artifacts
    • retrieval indexes
    • stored embeddings
    • RAG orchestration

    It is intended to make the difference between:

    • bird-image-model.pt
    • bird-sound-model.pt
    • SQLite and manifest-based indexes
    • OpenAI embedding-backed retrieval

    clear in one place.

    Quick Definitions¶

    Classifier artifact¶

    A classifier artifact is a saved trained model file that predicts a class label.

    Current examples:

    • bird-agent/models/bird-image-model.pt
    • bird-agent/models/bird-sound-model.pt

    These artifacts answer questions like:

    • "What bird is this image?"
    • "What bird is this recording?"

    Index¶

    An index is a lookup structure used for retrieval rather than direct classification.

    Current examples in this project:

    • SQLite tables such as bird_species, bird_detail, bird_species_sound_sources, and bird_species_rag_embeddings
    • training manifests such as gallery_sync_manifest.json and sound_training_manifest.json
    • local lexical retrieval structures built at runtime in bird-agent/rag.py

    Indexes answer questions like:

    • "What recordings do we have for this species?"
    • "Which birds best match this question?"
    • "Which images belong to this training set?"

    Stored embeddings¶

    Stored embeddings are saved numeric vectors representing text, images, or audio in a way that allows similarity search.

    In the current repo, the main embedding-backed path is the optional OpenAI retrieval mode for bird Q&A:

    • embeddings are stored in bird_species_rag_embeddings
    • retrieval is orchestrated in bird-agent/rag.py

    The project does not yet use a production vector index for image-identification or sound-identification inference. Those flows are currently classifier-first.

    Third-Party Processes And Services¶

    These flows depend on a mix of local libraries and external services.

    Image identification¶

    • PyTorch
    • model loading, tensors, training, inference
    • timm
    • model backbones such as efficientnet_b0
    • Pillow
    • image decode and preprocessing
    • Wikimedia Commons
    • optional external image-source enrichment
    • iNaturalist
    • optional external image-source enrichment
    • Firebase Storage
    • hosted app media and migrated gallery assets

    Sound identification¶

    • PyTorch
    • waveform tensors, resampling, spectrogram pipeline, training, inference
    • timm
    • CNN backbone for sound spectrogram classification
    • Swift with Apple audio frameworks
    • decode_audio.swift decodes MP3 audio during Mac-side training
    • xeno-canto
    • primary external bird-sound source
    • Wikimedia Commons
    • optional additional freely licensed sound source
    • Dropbox
    • curated Definitive MP3 source library
    • Firebase Storage
    • app-facing canonical media hosting when synced there

    Bird Q&A RAG¶

    • SQLite
    • source corpus and optional cached embedding rows
    • OpenAI Embeddings API
    • optional embedding generation for retrieval
    • OpenAI Chat API
    • optional answer generation
    • local lexical matching
    • default retrieval path when OpenAI is disabled or unavailable

    Image Identification Flow¶

    The image-identification path is currently classifier-first.

    flowchart TD A["User image in app
    camera or upload"] --> B["POST /identify-bird-image
    FastAPI route in main.py"] B --> C["Load classifier artifact
    bird-image-model.pt"] C --> D["Preprocess image
    Pillow + PyTorch transforms"] D --> E["Run CNN classifier
    timm backbone in PyTorch"] E --> F["Top species predictions
    top-1 / top-3 / confidence"] G["Reference image corpus
    gallery sync + Commons + iNaturalist"] --> H["Training dataset index
    species folders + manifests"] H --> I["train_bird_classifier.py"] I --> J["Classifier artifact output
    bird-image-model.pt"] J --> C F --> K["Look up species rows
    bird_species + bird_detail"] K --> L["Return structured result to app"]

    Artifact And Index Roles In The Image Flow¶

    • classifier artifact:
    • bird-agent/models/bird-image-model.pt
    • training index / reference structures:
    • species-labeled image folders
    • species.json
    • gallery_sync_manifest.json
    • production knowledge lookup:
    • bird_species
    • bird_detail

    Current Character¶

    This is not a RAG flow. It is:

    1. classify the image
    2. look up the predicted species details
    3. return metadata and media

    There is no production image embedding index being searched at inference time right now.

    Sound Identification Flow¶

    The sound-identification path now has training infrastructure in place, but the production app-facing classification endpoint is still the next step.

    flowchart TD A["External sound sources
    xeno-canto / Commons / Dropbox Definitive MP3"] --> B["Normalize and store sound files"] B --> C["Sound source index
    bird_species_sound_sources"] C --> D["prepare_sound_training_data.py"] D --> E["Training dataset index
    species folders + manifests"] E --> F["train_bird_sound_classifier.py"] F --> G["decode_audio.swift
    MP3 to WAV"] G --> H["PyTorch audio preprocessing
    resample + crop + log-mel spectrogram"] H --> I["CNN classifier
    timm backbone in PyTorch"] I --> J["Classifier artifact output
    bird-sound-model.pt"] K["Future user sound upload
    recording or file"] --> L["Future inference endpoint
    identify-bird-sound"] L --> M["Load classifier artifact
    bird-sound-model.pt"] M --> N["Decode + preprocess query audio"] N --> O["Predict likely species"] O --> P["Look up species rows
    bird_species + sound metadata"] P --> Q["Return structured result to app"]

    Artifact And Index Roles In The Sound Flow¶

    • classifier artifact:
    • bird-agent/models/bird-sound-model.pt
    • sound source index:
    • bird_species_sound_sources
    • training index / reference structures:
    • per-species dataset folders
    • species.json
    • sound_training_manifest.json
    • definitive_sound_manifest.json

    Current Character¶

    This is also classifier-first.

    What exists today:

    • sound ingestion
    • sound metadata indexing
    • sound dataset preparation
    • sound classifier training

    What is still next:

    • a production /identify-bird-sound endpoint
    • app wiring for sound classification results

    There is no production sound embedding search index in the inference path yet.

    Bird Q&A RAG Flow¶

    The bird-question flow is the clearest place where retrieval and optional embeddings already exist as a real runtime feature.

    flowchart TD A["User question in app"] --> B["POST /bird-questions/ask"] B --> C["rag.py orchestration"] D["bird_species rows
    structured species facts"] --> E["Build species documents"] E --> F{"Retrieval provider"} F -->|Local default| G["Lexical retrieval index
    token overlap over species documents"] F -->|OpenAI optional| H["Embedding model
    text-embedding-3-small by default"] H --> I["Stored embeddings index
    bird_species_rag_embeddings"] C --> F G --> J["Top matching species rows"] I --> J J --> K{"Answer provider"} K -->|Local default| L["Local answer builder"] K -->|OpenAI optional| M["Chat model
    gpt-4o-mini by default"] J --> L J --> M L --> N["Answer + matches returned to app"] M --> N H -.embedding refresh / rebuild.-> I

    Artifact And Index Roles In The Bird Q&A Flow¶

    • classifier artifact:
    • none
    • lexical index:
    • built from bird_species documents in runtime memory
    • stored embedding index:
    • bird_species_rag_embeddings
    • answer-generation model:
    • optional OpenAI chat model

    Current Character¶

    This is the main true RAG-style flow in the repo today.

    It works like this:

    1. retrieve relevant species rows
    2. optionally use embeddings for better similarity matching
    3. pass the retrieved context into an answer builder
    4. return an answer plus the matching birds

    Classifier-First Vs Retrieval-First¶

    The three flows are different by design.

    Image identification¶

    • primary decision mechanism:
    • classifier artifact
    • retrieval role:
    • lookup of species metadata after prediction

    Sound identification¶

    • primary decision mechanism:
    • classifier artifact
    • retrieval role:
    • lookup of species metadata and source recordings after prediction

    Bird Q&A¶

    • primary decision mechanism:
    • retrieval first
    • optional model role:
    • embedding model for retrieval
    • chat model for answer generation

    Where Each Saved Thing Lives¶

    Saved thing Type Current role
    bird-image-model.pt Classifier artifact Predict species from images
    bird-sound-model.pt Classifier artifact Predict species from sounds
    bird_species_rag_embeddings Stored embedding index Optional OpenAI retrieval for bird Q&A
    bird_species_sound_sources Metadata index Track available recordings and their provenance
    bird_detail Media/detail index Ordered species gallery and training metadata
    gallery_sync_manifest.json Manifest index Track gallery-to-training image provenance
    sound_training_manifest.json Manifest index Track per-species sound dataset contents
    definitive_sound_manifest.json Manifest index Track Dropbox sound import contents

    Practical Reading Of The System Today¶

    If the question is:

    • "What bird is in this photo?"
    • the answer comes from a classifier artifact
    • "What bird is making this sound?"
    • the training path is classifier-based, and the production endpoint is the next step
    • "Tell me about this bird" or "Which bird matches this question?"
    • the answer comes from retrieval and optional embedding-backed RAG

    That is the core distinction between:

    • classifier artifacts
    • indexes
    • stored embeddings
    • RAG orchestration
