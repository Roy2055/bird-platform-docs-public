    Setup Guide¶

    For the dedicated Plant backend, Plant Admin, and proposed GitHub Actions environment, see Environment Setup and Plant CI Integration.

    This project has two runnable applications:

    • bird-agent for the FastAPI backend
    • bird-app for the Expo mobile frontend
    • admin-web for the browser-based admin website

    Backend¶

    cd bird-agent
uv sync
cp .env.example .env
uv run uvicorn main:app --host 0.0.0.0 --port 8000 --reload

    Populate bird-agent/.env with:

    DATABASE_URL=postgresql://birdplatform:change-me@127.0.0.1:5432/bird_platform
FIREBASE_SERVICE_ACCOUNT_PATH=/absolute/path/to/service-account.json
FIREBASE_STORAGE_BUCKET=bird_platform_1
# Optional override for new prediction-media uploads.
# If omitted, the backend falls back to <firebase-project-id>.firebasestorage.app
FIREBASE_PREDICTION_STORAGE_BUCKET=bird-platform.firebasestorage.app
BIRD_RAG_RETRIEVAL_PROVIDER=local-semantic
BIRD_RAG_ANSWER_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
OLLAMA_BIRD_RAG_CHAT_MODEL=gemma3:4b

    Production database note:

    • use PostgreSQL for deployed environments
    • set DATABASE_URL to the application database connection string
    • keep local development aligned with the same schema where practical

    Optional OpenAI-powered bird-question configuration:

    OPENAI_API_KEY=your_openai_api_key_here
OPENAI_BIRD_RAG_EMBEDDING_MODEL=text-embedding-3-small
OPENAI_BIRD_RAG_CHAT_MODEL=gpt-4o-mini

    Recommended suitable Hetzner bird Q&A configuration:

    BIRD_RAG_RETRIEVAL_PROVIDER=local-semantic
BIRD_RAG_ANSWER_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434/v1
OLLAMA_BIRD_RAG_CHAT_MODEL=gemma3:4b

    CPU-only server notes:

    • enable swap before relying on Ollama on a 4GB VPS
    • cap Ollama context length for smaller memory pressure:
    [Service]
Environment="OLLAMA_CONTEXT_LENGTH=2048"
    • if gemma3:4b still OOM-kills the Ollama service, switch to a smaller chat model such as gemma3:1b

    API and Swagger docs:

    http://127.0.0.1:8000
http://127.0.0.1:8000/docs

    Frontend¶

    cd bird-app
npm install
cp .env.example .env
npx expo start

    Populate bird-app/.env with your Expo/Firebase client config, including:

    EXPO_PUBLIC_API_URL=http://127.0.0.1:8000
EXPO_PUBLIC_FIREBASE_API_KEY=your-key
EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN=your-project.firebaseapp.com
EXPO_PUBLIC_FIREBASE_PROJECT_ID=your-project-id
EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET=your-project.firebasestorage.app
EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your-sender-id
EXPO_PUBLIC_FIREBASE_APP_ID=your-app-id

    If you want to test the app on a phone over the same Wi‑Fi, set:

    EXPO_PUBLIC_API_URL=http://<your-computer-lan-ip>:8000

    For simulator or same-machine development, http://127.0.0.1:8000 is fine.

    Admin website¶

    cd admin-web
npm install
npm run dev

    For another computer on the same network, open the Vite URL from that machine and point the login screen at the backend API URL, for example:

    Admin site: http://192.168.1.50:4173
API URL:    http://192.168.1.50:8000

    AI and Dataset Setup¶

    Prepare or audit the classifier dataset:

    make agent-ai-prepare-all AI_DATASET_ROOT="/Volumes/DATA/training"
make agent-ai-audit AI_DATASET_ROOT="/Volumes/DATA/training"

    Train a classifier:

    cd bird-agent
.venv/bin/python -m ai.train_bird_classifier \
  --dataset-root "/Volumes/DATA/training" \
  --min-images-per-species 8 \
  --epochs 5 \
  --batch-size 8

    Media Sync¶

    Sync extra gallery images from the training dataset into the app-served uploads folder and bird_detail:

    make agent-detail-sync AI_DATASET_ROOT="/Volumes/DATA/training"

    Normalize existing species sounds:

    make agent-sound-sync

    Import missing sounds from xeno-canto:

    export XENO_CANTO_API_KEY="your_key_here"
make agent-xc-sound-sync

    Or place it in bird-agent/.env:

    XENO_CANTO_API_KEY=your_key_here

    Check structured sound-ingestion progress and retrieval:

    cd bird-agent
.venv/bin/python check_bird_sound_ingestion_progress.py
.venv/bin/python query_species_sounds.py "robin song uk"

    Backfill richer xeno-canto metadata for older selected rows:

    cd bird-agent
.venv/bin/python backfill_xeno_canto_sound_metadata.py --dry-run --limit 10
.venv/bin/python backfill_xeno_canto_sound_metadata.py --limit 10

    Firebase Media Migration¶

    Initial species/prediction media upload:

    cd bird-agent
.venv/bin/python migrate_media_to_firebase.py \
  --service-account "/absolute/path/to/service-account.json" \
  --bucket "bird_platform_1" \
  --sync-firestore

    Backfill older prediction images:

    .venv/bin/python backfill_prediction_media_to_firebase.py \
  --service-account "/absolute/path/to/service-account.json" \
  --bucket "bird_platform_1"

    Rewrite local media DB values to stable storage paths:

    .venv/bin/python cleanup_media_storage_paths.py

    Clean stale prediction image rows that still point at expiring signed URLs:

    .venv/bin/python cleanup_prediction_image_urls.py

    Apply only the safe rewrites:

    .venv/bin/python cleanup_prediction_image_urls.py --apply

    Stream mapped files directly from Dropbox cloud storage to Firebase and update the application database:

    .venv/bin/python migrate_dropbox_media_to_firebase.py \
  --service-account "/absolute/path/to/service-account.json" \
  --bucket "bird_platform_1" \
  --dropbox-token "your_dropbox_token" \
  --mapping-csv "data/dropbox_media_mapping.csv"

    If your Dropbox folder contains species gallery images with inconsistent names, generate a cleaned mapping CSV first:

    .venv/bin/python prepare_dropbox_species_gallery_mapping.py \
  --dropbox-dir "<path-to-dropbox-images>"

    Client Firebase Storage¶

    The current app uses a hybrid model:

    • species media is still read through backend API responses, which return signed cloud URLs
    • new prediction image and audio uploads can be sent directly from the Expo client to Firebase Storage
    • prediction image uploads now use a moderation flow:
    • upload to predictions/pending/{uid}/images/...
    • Firebase Function reviews the image
    • approved files move to predictions/approved/{uid}/images/...
    • the app waits for approval before saving image_url on the prediction
    • the backend upload endpoints remain as fallback and compatibility paths

    Community Feature Setup¶

    No extra service is required beyond the normal app/backend setup. Community data is stored in the main application database through the backend.

    Current community capabilities:

    • share/unshare predictions
    • star ratings
    • thumbs up/down reactions
    • comments
    • community-safe detail view for other users' shared predictions

    Deleting a prediction from Predictions removes it from Community as well.

    Bird Questions¶

    The Bird List screen includes a bird icon in the header that opens the bird-question panel.

    With the current default configuration:

    • retrieval provider is local
    • answer provider is local
    • no OpenAI key is required

    If OpenAI providers are enabled later, the same UI continues to work without frontend changes.

    Sound Ingestion Loop¶

    The sound-ingestion loop processes 3 birds every 20 seconds by default:

    cd <path-to-bird-platform>/bird-agent
.venv/bin/python run_sound_ingestion_loop.py

    Check status with:

    .venv/bin/python check_sound_ingestion_status.py

    Operational note:

    • do not run the sound-ingestion loop and the bird-data collection loop at the same time
    • both write to the application database and can contend under overlapping bulk-write workloads

    Backfill richer xeno-canto metadata into older source rows:

    .venv/bin/python backfill_xeno_canto_sound_metadata.py --dry-run --limit 10

    Important:

    • do not run the sound-ingestion loop and the bird text-data collection loop together
    • both write to the same application database and can interfere with each other during large ingestion runs

    Bird Species Data Collection Agent¶

    To backfill the newer extended bird_species text fields, run the backend collection agent from bird-agent/.

    Dry-run first:

    cd <path-to-bird-platform>/bird-agent
.venv/bin/python bird_data_collection_agent.py --dry-run --limit 5

    Write updates:

    .venv/bin/python bird_data_collection_agent.py --limit 5

    Useful options:

    • --species-id 42 run against one specific species id
    • --dry-run print the proposed field updates without writing database changes
    • --model gpt-4o-mini override the extraction model

    The agent only writes fields that are blank at save time, so existing populated values are preserved.

    Firebase Moderation Setup¶

    Prediction image moderation depends on all of the following:

    • Firebase Storage enabled
    • Firestore enabled
    • Cloud Vision API enabled
    • Functions deployed from firebase-functions/

    Useful commands:

    cd <path-to-bird-platform>/firebase-functions
npm install
npm run build

cd <path-to-bird-platform>
firebase deploy --only functions,storage

    Important bucket note:

    • legacy species and older migrated prediction media may still live in bird_platform_1
    • new moderated prediction uploads live in bird-platform.firebasestorage.app
    • the backend now resolves media from the correct bucket based on the storage path
