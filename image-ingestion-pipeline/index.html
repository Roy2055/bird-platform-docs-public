    Image Ingestion Pipeline¶

    This page documents the current image ingestion and image-training flow across Dropbox gallery imports, training dataset sync, and classifier training.

    Key scripts:

    • bird-agent/prepare_dropbox_species_gallery_mapping.py
    • bird-agent/import_hd_bird_detail_images.py
    • bird-agent/ai/prepare_training_data.py
    • bird-agent/ai/download_commons_images.py
    • bird-agent/ai/download_inaturalist_images.py
    • bird-agent/ai/sync_training_images_from_gallery.py
    • bird-agent/sync_bird_detail_images.py
    • bird-agent/ai/train_bird_classifier.py
    • bird-agent/ai/bird_image_identifier.py

    Main Source Paths¶

    1. Species gallery images¶

    The app-facing gallery is driven by:

    • bird_detail

    Important fields:

    • bird_species_id
    • image_url
    • display_order
    • image_quality
    • source_name
    • source_record_id
    • managed_by
    • managed_rank
    • is_managed

    Current meaning:

    • display_order controls gallery ordering
    • image_quality is training usefulness metadata, currently edited in the admin UI
    • source_name records the upstream source such as avicommons, wikimedia-commons, dropbox, or synced-gallery
    • source_record_id stores the source-specific identifier such as an Avicommons code:key pair or a filename/title
    • managed_by identifies the owning automation for refreshable rows
    • managed_rank stores the intended rank inside a managed gallery block
    • is_managed distinguishes automation-owned rows from legacy or manual rows

    2. Training dataset¶

    The classifier training dataset lives under a species-labeled root such as:

    • bird-agent/data/training
    • /Volumes/DATA/training

    Expected structure:

    training/
  1/
    species.json
    robin_001.jpg
    gallery_sync_manifest.json
  2/
    species.json
    blackbird_001.jpg

    Each top-level folder name must match bird_species.id.

    Image Ingestion Paths¶

    A. Dropbox gallery import¶

    Used for legacy gallery assets and migration work.

    Primary steps:

    1. scan a Dropbox folder of bird images
    2. map filenames to bird_species.common_name
    3. generate cleaned filenames and storage paths
    4. review the mapping CSV
    5. import or migrate into gallery storage
    6. insert/update bird_detail

    Main helper:

    • prepare_dropbox_species_gallery_mapping.py

    B. Gallery-to-training sync¶

    Used to turn the species gallery into a classifier dataset snapshot.

    Main helper:

    • sync_training_images_from_gallery.py

    Current behavior:

    • reads ordered species gallery rows
    • downloads image files from the configured storage bucket
    • writes a local training dataset
    • writes gallery_sync_manifest.json per species
    • preserves provenance such as:
    • bird_detail_id
    • source_path
    • filename
    • display_order
    • image_quality

    C. External source enrichment¶

    Used when a species needs more than the current gallery provides.

    Helpers:

    • prepare_training_data.py
    • download_commons_images.py
    • download_inaturalist_images.py

    Typical use:

    • seed every species with a reference/default image
    • add Commons or iNaturalist images
    • prioritize under-covered species

    D. Avicommons-first gallery refresh¶

    Used to refresh the leading gallery block with traceable managed rows.

    Main helper:

    • download_avicommons_thumbnails.py

    Current behavior:

    • matches Avicommons records first
    • fills remaining slots from Wikimedia Commons quality-image categories
    • uploads selected thumbnails to Firebase Storage
    • inserts or updates bird_detail rows with explicit provenance:
    • source_name
    • source_record_id
    • managed_by = download_avicommons_thumbnails
    • managed_rank
    • is_managed = 1
    • pushes the current desired managed set to the front of display_order
    • demotes stale older managed thumbnails to the end instead of deleting them
    flowchart TD
    A["Species id"] --> B["Match Avicommons records"]
    B --> C["Top up from Commons quality categories"]
    C --> D["Upload selected thumbnails to Firebase"]
    D --> E["Upsert managed bird_detail rows"]
    E --> F["Desired managed rows ordered first"]
    F --> G["Older stale managed rows demoted to end"]

    Useful full-run command for one managed lead image per species:

    cd bird-agent

.venv/bin/python -m ai.download_avicommons_thumbnails \
  --service-account "/absolute/path/to/service-account.json" \
  --bucket "bird_platform_1" \
  --all-species \
  --per-species 1 \
  --size 320

    Useful progress checks while that run is in flight:

    sqlite3 bird-agent/birds.db "
SELECT
  (SELECT COUNT(*) FROM bird_species) AS total_species,
  (SELECT COUNT(*)
   FROM bird_detail
   WHERE managed_by = 'download_avicommons_thumbnails'
     AND managed_rank = 1
     AND is_managed = 1) AS species_with_managed_lead_image;
"

    sqlite3 bird-agent/birds.db "
SELECT
  totals.total_species,
  totals.completed_species,
  ROUND((totals.completed_species * 100.0) / totals.total_species, 1) AS percent_complete
FROM (
  SELECT
    (SELECT COUNT(*) FROM bird_species) AS total_species,
    (SELECT COUNT(*)
     FROM bird_detail
     WHERE managed_by = 'download_avicommons_thumbnails'
       AND managed_rank = 1
       AND is_managed = 1) AS completed_species
) AS totals;
"

    sqlite3 bird-agent/birds.db "
SELECT
  bs.id,
  bs.common_name
FROM bird_species bs
LEFT JOIN bird_detail bd
  ON bd.bird_species_id = bs.id
 AND bd.managed_by = 'download_avicommons_thumbnails'
 AND bd.managed_rank = 1
 AND bd.is_managed = 1
WHERE bd.id IS NULL
ORDER BY bs.id ASC;
"

    Operational note:

    • the script currently prints only the final summary line
    • during the run it saves bird-agent/data/avicommons_thumbnail_manifest.json after each species, so that manifest file is the best non-SQL progress signal
    • summary.speciesProcessed is only finalized at the end, but the count of keys in manifest["species"] increases as species complete

    Useful non-SQL manifest check:

    cd bird-agent

python3 - <<'PY'
import json
from pathlib import Path

path = Path("data/avicommons_thumbnail_manifest.json")
payload = json.loads(path.read_text(encoding="utf-8"))
print("generatedAt:", payload.get("generatedAt"))
print("species entries:", len(payload.get("species", {})))
PY

    Training Flow¶

    The image classifier training flow is:

    1. prepare a species-labeled dataset root
    2. ensure each class meets a minimum image threshold
    3. split images per species into train / val / test
    4. train the selected backbone
    5. save the artifact to:
    6. bird-image-model.pt

    Current training script:

    • train_bird_classifier.py

    Current inference helper:

    • bird_image_identifier.py

    Current API:

    • POST /identify-bird-image

    Operational Notes¶

    • The gallery and the training dataset are related, but not identical.
    • A good gallery image is not always a good classifier image.
    • image_quality is intended to help separate display suitability from training suitability.
    • Managed gallery rows are now tracked explicitly in bird_detail; filename conventions such as thumb_... are only a legacy fallback.
    • External drives and SMB shares can hold the training dataset, but local disk is still the most reliable option for model training.

    Current Status¶

    What is already in place:

    • Dropbox-to-gallery mapping support
    • ordered species gallery in bird_detail
    • gallery-driven training sync
    • external-source enrichment scripts
    • image classifier training
    • saved image model artifact
    • backend image inference endpoint

    What is still iterative:

    • dataset curation quality
    • per-species image depth
    • model selection and retraining cadence
